# Source Of Truth Rules

These rules exist to prevent guessing. The project must match the current WordPress/Elementor/Figma system as closely as possible before CMS migration.

## Golden Rule

Do not guess. If a value is not confirmed by a real source, mark it as `needs confirmation` and continue only with the parts that are confirmed.

1. ACF export: `sources/acf-export-2026-05-19.json`

9. Full source analysis: stored in conversation artifacts.

## Source File Format Warning

All theme files in `sources/` are in **RTF format** (Rich Text Format), not raw code. Special characters are RTF-encoded (e.g., `\'e9` = é, `\'80` = €). When reading these files for logic extraction, decode RTF escapes mentally. Do NOT copy RTF markup into the Next.js codebase.

## Priority By Area

Configurator logic:

1. `single-houses.php`
2. `house-builder.js`
3. `house-builder.css`
4. ACF fields and WordPress XML values
5. Live site behavior

Layer mapping:

1. The exact `house_layers_*` values for the specific house in WordPress XML.
2. Attachment IDs and URLs referenced by those values.
3. User-provided layer files only after matching them to the confirmed `house_layers_*` key.

Never map a layer by filename alone. Filenames can be misleading.

Prices:

1. House-specific ACF/WordPress XML values.
2. Global option values from ACF/options data.
3. Existing WordPress JS calculation rules.

Design:

1. Figma for intended visual direction.
2. Elementor export for actual implemented layout settings.
3. Live website for final visual comparison.
4. Theme CSS where Elementor does not control the page.

CMS:

1. Build CMS schema only after local data model and frontend logic are stable.
2. CMS fields must reflect proven fields, not speculative fields.

## Required Checks Before Editing

Before changing configurator data:

- Identify the exact house post in WordPress XML.
- Read its `enable_*` flags.
- Read its `house_layers_*` values.
- Confirm whether the section exists for that house.
- Confirm the layer image by attachment ID, not only by filename.

Before changing Elementor-style pages:

- Read the corresponding `content/page/*.json` or `templates/*.json` from the Elementor zip.
- Note container width, padding, typography, colors, and widget type.
- Compare with the live page when possible.

Before changing checkout/order:

- Read `page-checkout.php`.
- Read `orders-viewer.php`.
- Confirm the session payload keys generated by configurator.
- Keep admin/customer email requirements visible.

## Required Checks After Completing Work

After every completed phase or meaningful feature:

- Update `PROJECT_ROADMAP.md` with what was completed, what was verified, and what remains risky.
- Update the relevant source-of-truth/audit document if a new confirmed rule, mapping, field, template, route, or exception was discovered.
- Record any temporary fallback as `needs confirmation`.
- Run the appropriate verification before calling the work complete.
- Suggest the next professional and safest phase based on the current dependency order, not on guesswork.

When suggesting the next phase:

- Prefer steps that reduce project risk.
- Prefer shared foundations before page-by-page polish.
- Prefer source extraction and reusable data structures before CMS migration.
- Do not suggest CMS schema changes until local logic and fields are proven.

## Configurator Completeness Checklist

Before a house configurator is considered complete, ALL of these must be verified:

1. **Data match**: All prices, surfaces, enable flags match WordPress XML exactly.
2. **Layer match**: All `house_layers_*` keys are mapped to correct attachment URLs.
3. **Section visibility**: Only sections allowed by enable flags are shown.
4. **Price formula**: `basePrice + Σ(option_price_per_m² × area) × 1.40 margin` matches live site.
5. **Size behavior**: Selecting 60x200 updates only isolation + faux plafond prices (uses `price_200`).
6. **Size reset**: Changing size clears ALL selections except size.
7. **Facade validation**: Cannot select facade without both isolations.
8. **Couverture/Terrasse exclusivity**: Selecting couverture hides terrasse and vice versa.
9. **Layer order**: Matches confirmed order from `single-houses.php`.
10. **Layer groups**: Selecting one option in a group deactivates others in same group.
11. **Window prices**: Uses per-house `aluminium_price` / `pvc_price`, NOT global option price.
12. **Checkout handoff**: sessionStorage payload matches WordPress `house-builder.js` structure.

## Frontend Verification Rules

Before any page is considered done:

1. **Open live site** at `https://ossaboisfrance.com/` side-by-side.
2. **Compare visually**: layout, spacing, colors, fonts, element order.
3. **Compare data**: titles, prices, descriptions, categories must match.
4. **Compare behavior**: clicks, toggles, calculations, validations must match.
5. **Run `npm run lint`**: zero errors.
6. **Run `npm run typecheck`**: zero errors.
7. **Run `npm run build`**: zero errors.
8. **Check browser console**: zero errors.
9. **Check responsive**: desktop (1200px+), tablet (768-992px), mobile (<768px).
